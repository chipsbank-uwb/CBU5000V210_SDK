APP-Flash

概述

本文档提供了使用开发板验证 Flash 外设基本读写功能的指南。该示例通过 UART 打印测试过程，依次完成 Flash 初始化、读取 Flash 信息、擦除扇区、写入测试数据、读回数据以及数据校验。

要求

  • 以下开发板之一：

    • CB5000V210 Anchor开发板

  • 软件：

    • 串行终端工具（例如 PuTTY, SSCOM）

用户界面

  • 串口连接:

    • 将 GPIO00 连接到串行接收线（RX）。

    • 将 GPIO01 连接到串行发送线（TX）。

  • 测试区域:

    • 示例擦除 Flash 扇区 0x40，对应测试地址 0x00040000。

    • 示例写入并读回 0x100 字节测试数据，数据内容为 0x00 到 0xFF。

  • 确保所有连接牢固，以避免通信问题。

构建和运行

  • 该示例可以在 ChipsBank Connect SDK 文件夹结构中的 Firmware\\Examples\\peripheral_flash 找到。

  • 编译并下载该例程到开发板后，复位开发板即可开始 Flash 基本操作测试。

测试

  1. 连接开发板

    • 准备一个合适的 USB 线，确保两端与您的计算机和开发板兼容。

    • 将 USB 线的一端插入计算机的 USB 端口，另一端插入开发板的 USB 端口。

    • 打开计算机上的设备管理器，检查是否识别到新的 COM 端口。如果没有，请检查 USB 线连接并确保安装了正确的驱动程序。

  2. 配置串行终端

    • 在计算机上打开串行终端工具，例如 PuTTY、SSCOM 或类似工具。

    • 在串行终端工具中选择识别到的 COM 端口。

    • 将波特率设置为 115200，停止位设置为 1，数据位顺序设置为 LSB，奇偶校验设置为 NONE。

    • 点击连接按钮以建立与开发板的串行通信。

  3. 重置开发板

    • 在开发板上找到复位按钮。

    • 按下并释放复位按钮以重启开发板。

  4. 观察串行输出

    • 复位后，在串行终端工具中观察输出。程序将打印 Flash 示例启动信息。

    • 示例会调用 cb_flash_init 初始化 Flash，并打印 Flash Vendor ID 和 Capacity。

    • 示例会擦除目标扇区，将 256 字节测试数据写入 0x00040000，随后读回到缓存并逐字节比较。

  5. 结果验证

    • 如果串口输出显示 All flash operations passed，表示擦除、写入、读取和数据校验均通过。

    • 如果出现 [ERROR] 输出，请根据失败步骤检查 Flash 初始化、地址范围、擦写操作或硬件连接。

预期输出

  • 复位开发板后，串行终端将显示类似以下输出。Flash Vendor ID 和 Capacity 会随实际 Flash 器件不同而变化。

=============================================
        Flash App Layer Example Start
=============================================
[INFO] Flash init success
[INFO] Flash Vendor ID: 0xEF
[INFO] Flash Capacity : 0x14
[INFO] Erase sector success
[INFO] Write data success
[INFO] Read data success

[INFO] All flash operations passed
=============================================

Overview

This document provides a guide to verify basic Flash peripheral read/write functionality using a development board. The example prints the test process through UART and executes Flash initialization, Flash information reading, sector erase, test data programming, data readback, and data verification.

Requirements

  • One of the following development boards:

    • CB5000V210 Anchor demo board

  • Software:

    • Serial terminal tool (e.g., PuTTY, SSCOM)

User interface

  • Serial Port Connections:

    • Connect GPIO00 to the serial receive line (RX).

    • Connect GPIO01 to the serial transmit line (TX).

  • Test Area:

    • The example erases Flash sector 0x40, which corresponds to test address 0x00040000.

    • The example writes and reads back 0x100 bytes of test data, from 0x00 to 0xFF.

  • Ensure all connections are secure to avoid communication issues.

Building and running

  • This sample can be found under Firmware\\Examples\\peripheral_flash in the ChipsBank Connect SDK folder structure.

  • Build and download the sample to the development board, then reset the board to start the basic Flash operation test.

Testing

  1. Connect the Development Board

    • Prepare a suitable USB cable, ensuring both ends are compatible with your computer and demo board.

    • Insert one end of the USB cable into a USB port on your computer and the other end into the USB port on the demo board.

    • Open the Device Manager on your computer to check if a new COM port has been recognized. If not, verify the USB cable connection and ensure the correct drivers are installed.

  2. Configure the Serial Terminal

    • Open a serial terminal tool on your computer, such as PuTTY, SSCOM, or any similar tool.

    • In the serial terminal tool, select the recognized COM port.

    • Set the baud rate to 115200, stop bits to 1, data bits order to LSB, and parity to NONE.

    • Click the connect button to establish serial communication with the development board.

  3. Reset the Development Board

    • Locate the reset button on the demo board.

    • Press and release the reset button to restart the development board.

  4. Observe Serial Output

    • After resetting the development board, observe the output in the serial terminal tool. The program prints the Flash example start message.

    • The example calls cb_flash_init to initialize Flash, and then prints the Flash Vendor ID and Capacity.

    • The example erases the target sector, writes 256 bytes of test data to 0x00040000, reads the data back into a buffer, and compares it byte by byte.

  5. Result Verification

    • If the serial output shows All flash operations passed, erase, write, read, and data verification operations all passed.

    • If an [ERROR] message appears, check the failed step, Flash address range, Flash operation status, and hardware connection.

Expected Output

  • The following output will be displayed in the serial terminal after resetting the development board. Flash Vendor ID and Capacity may vary depending on the actual Flash device.

=============================================
        Flash App Layer Example Start
=============================================
[INFO] Flash init success
[INFO] Flash Vendor ID: 0xEF
[INFO] Flash Capacity : 0x14
[INFO] Erase sector success
[INFO] Write data success
[INFO] Read data success

[INFO] All flash operations passed
=============================================
