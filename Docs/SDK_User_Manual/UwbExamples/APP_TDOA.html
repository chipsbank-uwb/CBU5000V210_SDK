APP-TDOA

概述

本文档提供了验证UWB到达时间差（TDOA）二维定位功能的指南。例程由一个Anchor Initiator、三个Anchor Responder和一个Tag组成。Initiator周期性发送Poll-DTM，Responder在各自时隙发送Resp-DTM，Tag接收四个基站的数据并计算三组距离差，随后向Initiator发送Tag-Report，由Initiator计算并输出Tag的二维坐标。

要求

  • 需要五块CBU5000V210开发板：

    • 一块作为Anchor Initiator（设备ID 0，时隙0）

    • 三块作为Anchor Responder（设备ID/时隙分别为1、2、3）

    • 一块作为Tag（设备ID 4）

  • 软件：

    • Keil MDK，用于编译和烧录三个TDOA工程

    • 串行终端工具（例如PuTTY、SSCOM）

  • 测试空间：

    • 四个Anchor应布置在同一二维平面，并尽量保持无遮挡视距（LOS）

    • Tag应放置在四个Anchor围成的有效定位区域内

用户界面

  • 在需要观察日志的开发板上，将GPIO00连接到串口接收线（RX），GPIO01连接到串口发送线（TX）。

  • Anchor Initiator串口参数设置为115200波特率、8个数据位、1个停止位、无奇偶校验。

  • 三个Anchor Responder和Tag串口参数设置为921600波特率、8个数据位、1个停止位、无奇偶校验。

  • 至少应观察Anchor Initiator串口；调试安装和标定问题时，建议同时观察三个Responder和Tag串口。

构建和运行

  • 例程位于ChipsBank Connect SDK的以下目录：

    • Firmware\\Examples\\uwb_tdoa_anchor_initiator

    • Firmware\\Examples\\uwb_tdoa_anchor_responder

    • Firmware\\Examples\\uwb_tdoa_tag

  • 分别编译并烧录Initiator、Responder和Tag工程。

  • 三块Responder使用同一个工程。编译每块Responder固件前，应在 AppUwbTdoaResponder.c 的 tdoa_role_apply_default_config() 中分别配置设备ID和时隙：

    • Responder 1：TDOA_DEFAULT_RESPONDER1_ID、APP_TDOA_RESPONDER1_SLOT

    • Responder 2：TDOA_DEFAULT_RESPONDER2_ID、APP_TDOA_RESPONDER2_SLOT

    • Responder 3：TDOA_DEFAULT_RESPONDER3_ID、APP_TDOA_RESPONDER3_SLOT

  • 不同Responder的设备ID和时隙不得重复，否则会发生响应碰撞并导致Tag缺失基站数据。

配置说明

  • 默认配置使用四个Anchor，坐标单位为米，基站编号与数组下标一致：

    • Anchor 0（Initiator）：(0.0, 0.0)

    • Anchor 1（Responder 1）：(0.0, 1.0)

    • Anchor 2（Responder 2）：(1.0, 0.0)

    • Anchor 3（Responder 3）：(1.0, 1.0)

  • 若实际基站位置与默认布局不同，必须同步修改 Firmware\\Components\\TdoaCommon\\tdoa_config.c 中的 g_tdoa_config.anchor_x[]、g_tdoa_config.anchor_y[] 配置；若基站数量发生变化，还需同步检查 g_tdoa_config.anchor_count。

  • anchor_x[] 和 anchor_y[] 的单位为米。数组下标必须与设备ID对应，并确保Anchor Initiator最终使用的坐标配置与现场基站位置完全一致，否则计算出的Tag坐标会产生系统性偏差。

  • 修改公共配置后，应重新编译并烧录所有受影响的TDOA工程，避免不同设备使用不一致的配置。

测试

  1. 布置和连接开发板

    • 按 tdoa_config.c 中配置的坐标布置四个Anchor，并记录每块板对应的设备ID。

    • 将Tag放置在基站区域内的已知位置，便于对比定位结果。

    • 连接USB和串口，确认各开发板均能正常上电并输出日志。

  2. 启动Anchor Initiator

    • 烧录并复位Anchor Initiator。

    • 串口应显示 TDOA Initiator v1.0、配置加载信息和 Initiator ready。

  3. 依次启动三个Anchor Responder

    • 建议依次复位Responder 1、Responder 2和Responder 3，并等待当前Responder完成启动标定后再启动下一块。

    • 每个Responder启动后会与Initiator执行约3秒的DS-TWR采样标定，并锁定传播时间偏差参数。

    • 确认串口显示的Responder设备ID和时隙与计划一致，并出现 boot calib done。

  4. 启动Tag并观察定位结果

    • 烧录并复位Tag，确认出现 TDOA Tag v1.0 和 RX started。

    • Initiator每10ms启动一轮TDOA过程。Tag接收Poll-DTM及三个Resp-DTM，计算DIS01、DIS02、DIS03并发送Tag-Report。

    • Initiator接收Tag-Report后运行位置解算，并输出 POS_CALC POS:(x, y)。

    • 移动Tag到不同已知位置，观察Anchor Initiator串口打印的坐标是否随位置变化且保持稳定。

预期输出

  • Anchor Initiator串口输出示例（距离差和坐标值随实际位置变化）：

TDOA Initiator v1.0
TDOA: config loaded from defaults (id=0 slot=0)
[INIT] Initiator ready, Timer0=10ms
[INIT] boot calib done, resume TDOA
[R:125] DIS01: 12.345 cm,DIS02: -8.210 cm,DIS03: 4.876 cm | POS_CALC POS:(0.420, 0.580) ITER:3

  • Tag串口输出示例：

[TAG] TDOA Tag v1.0
TDOA: config loaded from defaults (id=4 slot=0)
[TAG] init, RX started
[R:125] DIS01:12.345cm,DIS02:-8.210cm,DIS03:4.876cm RATIO:1.00000000 STAT:ok=125,lost=0

  • Responder串口输出示例：

[RESP] TDOA Responder v1.0
TDOA: config loaded from defaults (id=1 slot=1)
[RESP] init, id=1 slot=1, boot calib started
[CALIB RESP] locked tp_bias_cm=100.00 sample=128
[RESP] boot calib done, tp_bias_cm=100.00

故障排查

  • Anchor Initiator端持续输出 NO TAG REPORT!：检查Tag是否已启动、UWB参数是否一致，以及Tag是否处于有效接收范围内。

  • Anchor Initiator端输出 LACK_ANCHOR、TAG_DBG，或Tag端的 lost 计数持续增加：检查三个Responder的设备ID/时隙是否唯一，并检查天线遮挡、供电和基站间距。

  • Anchor Responder端反复出现标定超时：先确认软件配置和启动顺序，再检查Initiator是否正常运行、串口日志所示ID是否正确，最后排查天线连接和射频环境。

  • Anchor Initiator端输出的坐标稳定但存在固定偏差：优先核对 tdoa_config.c 中的基站坐标、坐标单位、基站编号和现场位置是否一致。

Overview

This document provides a guide to verify two-dimensional Time Difference of Arrival (TDOA) positioning with UWB. The example consists of one Anchor Initiator, three Anchor Responders, and one Tag. The Initiator periodically transmits Poll-DTM frames, the Responders transmit Resp-DTM frames in their assigned slots, and the Tag receives all four anchor frames and calculates three distance differences. The Tag then sends a Tag-Report to the Initiator, which calculates and prints the two-dimensional Tag position.

Requirements

  • Five CBU5000V210 development boards:

    • One Anchor Initiator (device ID 0, slot 0)

    • Three Anchor Responders (device IDs and slots 1, 2, and 3)

    • One Tag (device ID 4)

  • Software:

    • Keil MDK for building and programming the three TDOA projects

    • Serial terminal tool (e.g., PuTTY or SSCOM)

  • Test area:

    • Place the four Anchors on the same two-dimensional plane with a clear line of sight (LOS) whenever possible

    • Place the Tag inside the effective positioning area enclosed by the Anchors

User interface

  • On each board whose logs need to be monitored, connect GPIO00 to the serial receive line (RX) and GPIO01 to the serial transmit line (TX).

  • Configure the Anchor Initiator serial port for 115200 baud, 8 data bits, 1 stop bit, and no parity.

  • Configure the three Anchor Responder and Tag serial ports for 921600 baud, 8 data bits, 1 stop bit, and no parity.

  • Monitor at least the Anchor Initiator serial output. Monitoring all three Responders and the Tag is recommended when debugging installation or calibration problems.

Building and running

  • The examples are located in the following ChipsBank Connect SDK directories:

    • Firmware\\Examples\\uwb_tdoa_anchor_initiator

    • Firmware\\Examples\\uwb_tdoa_anchor_responder

    • Firmware\\Examples\\uwb_tdoa_tag

  • Build and program the Initiator, Responder, and Tag projects separately.

  • All three Responder boards use the same project. Before building the firmware for each Responder, configure its device ID and slot in tdoa_role_apply_default_config() in AppUwbTdoaResponder.c:

    • Responder 1: TDOA_DEFAULT_RESPONDER1_ID and APP_TDOA_RESPONDER1_SLOT

    • Responder 2: TDOA_DEFAULT_RESPONDER2_ID and APP_TDOA_RESPONDER2_SLOT

    • Responder 3: TDOA_DEFAULT_RESPONDER3_ID and APP_TDOA_RESPONDER3_SLOT

  • Responder device IDs and slots must be unique. Duplicated values cause response collisions and missing-anchor data at the Tag.

Configuration

  • The default configuration uses four Anchors. Coordinates are in metres and each Anchor number matches its array index:

    • Anchor 0 (Initiator): (0.0, 0.0)

    • Anchor 1 (Responder 1): (0.0, 1.0)

    • Anchor 2 (Responder 2): (1.0, 0.0)

    • Anchor 3 (Responder 3): (1.0, 1.0)

  • If the physical Anchor positions differ from the default layout, update g_tdoa_config.anchor_x[] and g_tdoa_config.anchor_y[] in Firmware\\Components\\TdoaCommon\\tdoa_config.c. If the number of Anchors changes, also verify g_tdoa_config.anchor_count.

  • The anchor_x[] and anchor_y[] values are expressed in metres. Each array index must match the corresponding device ID, and the final coordinate configuration used by the Anchor Initiator must exactly match the physical Anchor layout. Otherwise, the calculated Tag position will contain a systematic error.

  • After changing the common configuration, rebuild and reprogram every affected TDOA project so that devices do not operate with inconsistent settings.

Testing

  1. Place and Connect the Boards

    • Place the four Anchors according to the coordinates configured in tdoa_config.c and record the device ID assigned to each board.

    • Place the Tag at a known point inside the Anchor area so the calculated position can be compared with the physical position.

    • Connect USB and serial cables, then confirm that every board powers on and prints logs.

  2. Start the Anchor Initiator

    • Program and reset the Anchor Initiator.

    • The serial terminal should display TDOA Initiator v1.0, the loaded configuration, and Initiator ready.

  3. Start the Three Anchor Responders in Sequence

    • Reset Responder 1, Responder 2, and Responder 3 in sequence. It is recommended to wait until the current Responder completes boot calibration before starting the next one.

    • At startup, each Responder performs an approximately three-second DS-TWR sampling calibration with the Initiator and locks its propagation-time bias parameter.

    • Verify that the device ID and slot printed by each Responder match the intended values and that boot calib done is displayed.

  4. Start the Tag and Observe Positioning Results

    • Program and reset the Tag. Verify that TDOA Tag v1.0 and RX started are displayed.

    • The Initiator starts a TDOA round every 10 ms. The Tag receives the Poll-DTM and three Resp-DTM frames, calculates DIS01, DIS02, and DIS03, and transmits a Tag-Report.

    • After receiving the Tag-Report, the Initiator runs the position solver and prints POS_CALC POS:(x, y).

    • Move the Tag to different known positions and observe the coordinates printed by the Anchor Initiator serial terminal. Verify that they change accordingly and remain stable.

  • Example Anchor Initiator output (distance differences and coordinates vary with the physical position):

  • Example Tag output:

Troubleshooting

  • If the Anchor Initiator continuously prints NO TAG REPORT!, verify that the Tag is running, all devices use matching UWB parameters, and the Tag is within reception range.

  • If the Anchor Initiator prints LACK_ANCHOR or TAG_DBG, or the Tag-side lost counter keeps increasing, verify that all Responder device IDs and slots are unique, then check antenna obstruction, power, and Anchor spacing.

  • If an Anchor Responder repeatedly reports calibration timeouts, first verify the software configuration and startup order, then confirm that the Initiator is running and the printed device ID is correct. Check antenna connections and the RF environment last.

  • If the coordinates printed by the Anchor Initiator are stable but contain a fixed offset, first verify that the Anchor coordinates, units, device mapping, and physical layout match the settings in tdoa_config.c.
