APP-DSTWR-1TO5

概述

本文档提供了验证一对多（一个发起者对最多五个响应者）双面双向测距（DS-TWR）功能的指南。该示例在标准DS-TWR的基础上增加了设备发现机制：发起者广播SCAN消息自动发现周围的响应者并建立设备列表，随后按列表逐个与响应者完成一次完整的DS-TWR测距，并将测得的距离回传给该响应者，因此发起者和响应者都能打印出距离结果和对端（responder）的设备ID。

要求

  • 需要以下开发板中的两个至六个：

    • CB5000V210 Anchor开发板（一个作为发起者，最多五个作为响应者）

  • 软件：

    • 串行终端工具（例如PuTTY、SSCOM）

用户界面

  • 在每个开发板上找到GPIO00引脚，并将其连接到串行接收线（RX）。

  • 在每个开发板上找到GPIO01引脚，并将其连接到串行发送线（TX）。

  • 确保连接牢固，以避免通信问题。

构建和运行

  • 该示例可以在ChipsBank Connect SDK文件夹结构中的以下位置找到：

    • ”Firmware\Examples\uwb_ds_twr_initiator_1to5”

    • ”Firmware\Examples\uwb_ds_twr_responder_1to5”

工作流程

Initiator                        Responder (最多5个)
 Idle                                Idle
   |--------0a. SCAN(广播)---------->|
   |<-------0b. ID(0x55 0xAA + ID)---|  随机退避后应答
   |--------1. SYNC(目标ID)--------->|
   |<-------2. ACK-------------------|
 a |--------3. DSTWR(POLL)---------->| d
 b |<-------4. DSTWR(RESPONSE) ------| e
 c |--------5. DSTWR(FINAL) -------->| f
   |<-------6. RESULT ---------------|
   |--------7. DISTANCE ------------>|
 Terminate                         Terminate

  • 0a/0b：设备发现阶段。发起者广播4字节的”SCAN”消息，响应者收到后以”0x55 0xAA + 芯片ID低4字节”应答。为避免多个响应者同时应答造成碰撞，每个响应者以自身芯片ID作为随机数种子，退避 (1~100)×300us 后再发送应答。

  • 发起者的扫描窗口为30ms，窗口内最多记录5个（SUPPORT_MAX_DEVICE）设备；集满5个或窗口超时后进入测距阶段。若窗口内一个设备也没有发现，则重新广播SCAN。

  • 1/2：发起者从设备列表中取出一个设备，将该设备的4字节ID作为SYNC消息的载荷发送出去。只有ID匹配的响应者才会回复ACK并参与本次测距，其余响应者继续等待。

  • 3~6：与标准DS-TWR一致，POLL/RESPONSE/FINAL的收发由UWB绝对定时器调度，响应者最后把Tround/Treply时间戳数据回传给发起者，由发起者计算距离。

  • 7：发起者把计算出的距离（单位cm，4字节大端整数）发送给响应者，使响应者也能打印距离结果。

  • 一次测距结束后，发起者对列表中的下一个设备重复1~7；列表清空后重新执行SCAN。

测试

  1. 连接开发板

    • 准备合适的USB线，确保两端与您的计算机和开发板兼容。

    • 将USB线的一端插入计算机的USB端口，另一端插入开发板的USB端口。

    • 打开计算机上的设备管理器，检查是否识别到新的COM端口。如果没有，请检查USB线连接并确保安装了正确的驱动程序。

  2. 配置串行终端

    • 在计算机上为每块开发板各打开一个串行终端工具，例如PuTTY、SSCOM或类似工具。

    • 在每个串行终端工具中选择识别到的COM端口。

    • 将波特率设置为115200，停止位设置为1，数据位顺序设置为LSB，奇偶校验设置为NONE。

    • 点击连接按钮以建立与每个开发板的串行通信。

  3. 烧录并重置开发板

    • 将一个开发板刷入uwb_ds_twr_initiator_1to5固件，其余开发板（最多五个）刷入uwb_ds_twr_responder_1to5固件。

    • 响应者固件无需逐个修改，各设备通过芯片ID自动区分。

    • 在每个开发板上找到复位按钮，按下并释放以重启每个开发板。

  4. 执行测试操作

    • 重置后，观察串行终端工具中的输出。

    • 发起者将开始一对多DS-TWR过程：

      1. 广播SCAN消息并等待30ms，收集响应者上报的设备ID

      2. 打印”scan timer out:N”，N为本次扫描发现的设备数量

      3. 逐个向设备列表中的响应者发送SYNC消息（载荷为目标设备ID）

      4. 等待响应者的ACK响应

      5. 依次完成POLL、RESPONSE、FINAL的收发

      6. 接收来自响应者的RESULT消息并计算距离

      7. 将距离回传给响应者，打印距离和对端设备ID

    • 每个响应者将：

      1. 接收SCAN消息，随机退避后上报自身芯片ID

      2. 接收SYNC消息并与自身芯片ID比对，不匹配则继续等待

      3. 匹配时向发起者回复ACK消息

      4. 接收POLL、发送RESPONSE、接收FINAL

      5. 向发起者发送RESULT（Tround/Treply时间戳数据）

      6. 接收发起者回传的距离并打印距离和自身设备ID

    • 观察所有开发板上的串行终端输出以验证成功的距离测量。

    • 如果在测距过程中发生超时（DEF_DSTWR_OVERALL_PROCESS_TIMEOUT_MS为10ms），错误消息将指示哪个阶段失败。

    • 若SYNC后10ms（DEF_DSTWR_SYNC_ACK_TIMEOUT_MS）内未收到ACK，发起者将重新发起扫描或对下一个设备测距。

Overview

This document provides a guide to verify the functionality of one-to-many (one initiator against up to five responders) Double-Sided Two-Way Ranging (DS-TWR) using UWB technology. On top of the standard DS-TWR flow, this example adds a device discovery mechanism: the initiator broadcasts a SCAN message to discover the surrounding responders and builds a device list, then performs a complete DS-TWR ranging sequence with each responder in turn and sends the measured distance back to that responder. As a result, both the initiator and the responders print the distance result together with the peer device ID.

Requirements

  • Two to six of the following development boards:

    • CB5000V210 Anchor demo boards (one as initiator, up to five as responders)

  • Software:

    • Serial terminal tool (e.g., PuTTY, SSCOM)

User interface

  • Locate the GPIO00 pin on each development board and connect it to the serial receive line (RX).

  • Locate the GPIO01 pin on each development board and connect it to the serial transmit line (TX).

  • Ensure the connections are secure to avoid communication issues.

Building and running

This sample can be found under the following locations in the ChipsBank Connect SDK folder structure:

  • “Firmware\Examples\uwb_ds_twr_initiator_1to5”

  • “Firmware\Examples\uwb_ds_twr_responder_1to5”

Operation flow

Initiator                        Responder (up to 5)
 Idle                                Idle
   |--------0a. SCAN (broadcast)---->|
   |<-------0b. ID (0x55 0xAA + ID)--|  replies after random backoff
   |--------1. SYNC (target ID)----->|
   |<-------2. ACK  -----------------|
 a |--------3. DSTWR(POLL) --------->| d
 b |<-------4. DSTWR(RESPONSE) -----| e
 c |--------5. DSTWR(FINAL) -------->| f
   |<-------6. RESULT --------------|
   |--------7. DISTANCE ------------>|
 Terminate                         Terminate

  • 0a/0b: Device discovery stage. The initiator broadcasts a 4-byte “SCAN” message, and each responder replies with “0x55 0xAA + the lower 4 bytes of its chip ID”. To avoid collisions when several responders reply at the same time, each responder uses its own chip ID as the random seed and backs off for (1~100)×300us before sending the reply.

  • The scan window of the initiator is 30ms, and up to five devices (SUPPORT_MAX_DEVICE) are recorded within the window. The ranging stage starts once five devices are collected or the window expires. If no device is discovered within the window, the SCAN message is broadcast again.

  • 1/2: The initiator takes one device from the device list and sends its 4-byte ID as the payload of the SYNC message. Only the responder whose ID matches replies with an ACK and takes part in this ranging cycle, while the other responders keep waiting.

  • 3~6: Identical to the standard DS-TWR flow. The POLL/RESPONSE/FINAL transmissions are scheduled by the UWB absolute timer, and the responder finally sends the Tround/Treply timestamp data back so that the initiator can calculate the distance.

  • 7: The initiator sends the calculated distance (in cm, 4-byte big-endian integer) to the responder, so that the responder can print the distance result as well.

  • After one ranging cycle completes, the initiator repeats steps 1~7 for the next device in the list. Once the list is empty, the SCAN stage is executed again.

Testing

  1. Connect the Development Boards

    • Prepare suitable USB cables, ensuring both ends are compatible with your computer and demo boards.

    • Insert one end of each USB cable into USB ports on your computer and the other ends into the USB ports on the demo boards.

    • Open the Device Manager on your computer to check if new COM ports have been recognized. If not, verify the USB cable connections and ensure the correct drivers are installed.

  2. Configure the Serial Terminals

    • Open one serial terminal tool per development board on your computer, such as PuTTY, SSCOM, or any similar tool.

    • In each serial terminal tool, select the recognized COM port for each board.

    • Set the baud rate to 115200, stop bits to 1, data bits order to LSB, and parity to NONE.

    • Click the connect button to establish serial communication with each development board.

  3. Program and Reset the Development Boards

    • Program one development board with the uwb_ds_twr_initiator_1to5 firmware and the remaining boards (up to five) with the uwb_ds_twr_responder_1to5 firmware.

    • The responder firmware does not need to be modified per board, as the devices are distinguished automatically by their chip IDs.

    • Locate the reset button on each demo board, then press and release it to restart each development board.

  4. Execute Test Operations

    • After resetting, observe the output in the serial terminal tool.

    • The Initiator will begin the one-to-many DS-TWR process by:

      1. Broadcasting the SCAN message and waiting 30ms to collect the device IDs reported by the responders

      2. Printing “scan timer out:N”, where N is the number of devices discovered in this scan

      3. Sending a SYNC message (with the target device ID as payload) to each responder in the device list

      4. Waiting for an ACK response from the responder

      5. Completing the POLL, RESPONSE and FINAL exchanges in sequence

      6. Receiving the RESULT message from the responder and calculating the distance

      7. Sending the distance back to the responder and printing the distance and the peer device ID

    • Each Responder will:

      1. Receive the SCAN message and report its own chip ID after a random backoff

      2. Receive the SYNC message and compare it with its own chip ID, and keep waiting if it does not match

      3. Send an ACK message back to the Initiator when it matches

      4. Receive the POLL message, send the RESPONSE message and receive the FINAL message

      5. Send the RESULT message (Tround/Treply timestamp data) to the Initiator

      6. Receive the distance sent back by the Initiator and print the distance and its own device ID

    • Observe the serial terminal outputs on all boards to verify successful distance measurement.

    • If a timeout occurs during ranging (DEF_DSTWR_OVERALL_PROCESS_TIMEOUT_MS is 10ms), an error message will indicate which stage failed.

    • If no ACK is received within 10ms (DEF_DSTWR_SYNC_ACK_TIMEOUT_MS) after SYNC, the initiator restarts the scan or moves on to the next device.
